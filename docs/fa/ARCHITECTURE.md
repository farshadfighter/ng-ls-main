# سند معماری امنیتی سرور لایسنس NGCorion

| مورد | مقدار |
|---|---|
| محصول | سرور لایسنس NGCorion |
| نسخهٔ محصول | 2.0.0 |
| نسخهٔ سند | 1.0 |
| الزام معیار مشترک | ADV_ARC.1؛ پشتیبان ADV_TDS.1 و ADV_FSP.2 |
| اسناد مرتبط | [هدف امنیتی](../SECURITY_TARGET.md)، [راهنمای نصب و راهبری](ADMIN_GUIDE.md)، `SECURITY.md`، `ACME.md` |

این سند اجزای سرور لایسنس، مرزهای اعتماد، جریان داده‌ها و ویژگی‌های معماری امنیتی (راه‌اندازی امن،
حفاظت از خود، جداسازی دامنه، عدم‌امکان دور زدن) را با ارجاع به کد شرح می‌دهد.

---

## ۱. نمای کلی

```
                       ┌──────────────────────── مرز TOE ───────────────────────────┐
 NGCorion ها ──443──►  │ Traefik ──(lic.ngcorion.com: TLS، Let's Encrypt)──► nginx :8081 │
 مرورگر مدیران ─────►  │    └─(IP / نام‌های دیگر: عبور رمزشده)─────────────► nginx :8443 │
 پورتال فروش ─────►    │                    PROXY protocol: نشانی واقعی مشتری         │
                       │ nginx: کنسول React + پراکسی ─► backend (FastAPI، :8001)       │
                       │                                   │            │             │
                       │                              PostgreSQL      Redis           │
                       └──────────────────────────────────────────────────────────────┘
                                                           │
                                       رویدادهای لایسنس ──► پورتال فروش (JWT امضاشده)
```

| زیرسیستم | نقش امنیتی | محل |
|---|---|---|
| Traefik (اختیاری با ACME) | TLS برای `lic.ngcorion.com` با گواهی عمومی؛ ALPN فقط http/1.1؛ عبور رمزشدهٔ سایر نام‌ها | `docker-compose.acme.yml`، `traefik/dynamic.yml` |
| nginx | TLS 1.2+ (AEAD)، سرآیندهای امنیتی و CSP، سقف بدنه ۶۴KB، فهرست مجاز IP برای `/internal/`، بازنویسی `X-Real-IP`/`X-Forwarded-For` | `license-admin-ui/nginx.conf` |
| کنسول مدیریت | رابط React؛ هیچ منطق امنیتی سمت مرورگر به آن تکیه نمی‌شود | `license-admin-ui/src/` |
| میان‌افزار | محدودیت نرخ به‌ازای نشانی (Redis، اتمیک)، لاگ درخواست | `app/middleware/` |
| API لایسنس | فعال‌سازی، اعتبارسنجی، heartbeat؛ پاسخ امضاشده | `app/routers/licenses.py`، `app/crud.py`، `app/utils/license_token.py` |
| حساب‌ها و نشست‌ها | حساب شخصی، نقش، رمز، قفل، نشست سمت سرور | `app/accounts.py`، `app/core/security.py`، `app/core/passwords.py` |
| API مدیریت | لایسنس، حساب‌ها، ممیزی، پورتال | `app/routers/admin*.py` |
| دنبالهٔ ممیزی | ثبت و حفاظت رویدادها | `app/audit.py`، `models.AUDIT_GUARD_SQL`، مهاجرت `008` |
| لایسنس آفلاین | صدور و بررسی فایل امضاشده | `app/offline.py` |
| اتصال پورتال | ورودی: IP + JWT + jti یک‌بارمصرف؛ خروجی: رویداد امضاشده | `app/core/portal_*.py`، `app/routers/internal_portal.py` |
| خط فرمان بازیابی | مدیریت حساب روی میزبان، ممیزی‌شده | `app/cli.py` |

## ۲. مرزهای اعتماد و جریان‌ها

| # | جریان | حفاظت |
|---|---|---|
| 1 | NGCorion → `/api/licenses/*` | TLS با گواهی عمومی؛ ورودی محدود (کلید ≤ ۶۴، اثر انگشت ۱۶ تا ۱۲۸ نویسهٔ هگز، توکن ≤ ۱۲۸)؛ محدودیت نرخ؛ پاسخ امضاشده با nonce مشتری. |
| 2 | مرورگر مدیر → کنسول و `/api/admin/*` | TLS؛ Turnstile در ورود؛ JWT نشست + نشست سمت سرور؛ نقش در هر درخواست. |
| 3 | پورتال فروش → `/internal/portal/*` | فهرست مجاز IP در nginx و برنامه؛ JWT HS256 با `PORTAL_JWT_SECRET` (جدا از `SECRET_KEY`)، iss/aud، عمر کوتاه، `jti` یک‌بارمصرف در Redis. |
| 4 | سرور لایسنس → پورتال | رویدادهای لایسنس با JWT امضاشده، تلاش دوباره با تأخیر نمایی. |
| 5 | nginx → backend، backend → PostgreSQL/Redis | شبکهٔ داخلی Docker؛ backend منتشر نمی‌شود؛ Redis با رمز. |
| 6 | Traefik → nginx | PROXY protocol v2؛ nginx فقط از شبکه‌های خصوصی به آن اعتماد می‌کند (`set_real_ip_from`). |

**تعیین نشانی مشتری:** nginx `X-Real-IP` و `X-Forwarded-For` را با `$remote_addr` (پس از PROXY
protocol) بازنویسی می‌کند؛ برنامه فقط `X-Real-IP` را می‌خواند، پس سرآیندی که مشتری بفرستد اثری بر
محدودیت نرخ، فهرست مجاز یا رکورد ممیزی ندارد.

## ۳. پاسخ امضاشدهٔ لایسنس

قالب: `base64url(JSON ادعاها) "." base64url(امضای Ed25519 روی همان بایت‌ها)`.

ادعاها: نسخهٔ توکن، شناسهٔ کلید، نوع پاسخ (activate/validate/heartbeat/offline)، کلید لایسنس، اثر
انگشت ماشین، نتیجه و پیام، طرح (کد و نام)، سقف دارایی و بسته‌های افزودنی، انقضای لایسنس، زمان صدور،
و **nonce** که مشتری فرستاده است (جلوگیری از بازپخش).

* کلید خصوصی فقط از `LICENSE_SIGNING_PRIVATE_KEY` در محیط میزبان خوانده می‌شود؛ در لاگ، پاسخ، گیت
  و ایمیج نیست. `GET /api/signing-key` فقط کلید عمومی و شناسهٔ آن را برمی‌گرداند.
* **یک لایسنس، یک ماشین:** اولین فعال‌سازی اثر انگشت را ثبت می‌کند؛ ماشین دیگر تا آزاد شدن اتصال
  توسط اپراتور رد می‌شود.
* اعتبارسنجی کلید، توکن سازمان (مقایسهٔ زمان‌ثابت) و اثر انگشت را می‌خواهد؛ کلید ناشناخته و توکن
  نادرست پاسخ یکسان می‌گیرند.
* **فایل آفلاین:** همان قالب با نوع `offline`، گره‌خورده به یک ماشین، با `offline_until` حداکثر یک
  سال و نه بیش از انقضای لایسنس؛ هر صدور ثبت می‌شود.

## ۴. معماری امنیتی (ADV_ARC.1)

### ۴.۱ راه‌اندازی امن

| مرحله | تضمین | محل |
|---|---|---|
| پیکربندی | Compose بدون `SECRET_KEY`، `ADMIN_PASSWORD`، `TURNSTILE_SECRET_KEY`، `LICENSE_SIGNING_PRIVATE_KEY`، `REDIS_PASSWORD` و `PORTAL_JWT_SECRET` اجرا نمی‌شود؛ `SECRET_KEY` کوتاه‌تر از ۳۲ نویسه برنامه را متوقف می‌کند. | `docker-compose.yml`، `app/core/config.py` |
| ایمیج | `.env` در ایمیج نیست (`.dockerignore`)؛ backend با کاربر غیرممتاز (UID 10001) اجرا می‌شود. | `license_server/Dockerfile` |
| شروع | مهاجرت‌های Alembic؛ ساخت اولین مدیر فقط اگر هیچ حسابی وجود ندارد (با تغییر اجباری رمز)؛ ثبت `system.start` با شناسهٔ کلید امضا در دنبالهٔ ممیزی. | `entrypoint.sh`، `app/accounts.py`، `app/main.py` |
| مستندات API | `/docs` و `/openapi.json` به‌طور پیش‌فرض خاموش (`ENABLE_API_DOCS=False`). | `app/core/config.py` |

### ۴.۲ حفاظت از خود

* **رمزها:** scrypt با نمک تصادفی؛ سیاست ۱۲ نویسه و سه نوع نویسه، بدون نام کاربری.
* **نشست:** JWT HS256 با `SECRET_KEY` (≥ ۲۵۶ بیت)، iss/aud، و ارجاع به نشست سمت سرور که با خروج،
  بی‌کاری ۱۵ دقیقه، ۸ ساعت عمر، تغییر رمز یا غیرفعال شدن حساب بسته می‌شود.
* **قفل حساب:** ۵ شکست ← ۱۵ دقیقه؛ همهٔ ردها پاسخ و زمان یکسان دارند (جلوگیری از شمارش حساب‌ها).
* **دنبالهٔ ممیزی:** تریگر پایگاه داده UPDATE و DELETE روی `audit_events` را رد می‌کند؛ رمز، توکن و
  کلید هرگز ثبت نمی‌شوند.
* **ورودی:** طول و الگوی همهٔ ورودی‌ها محدود است (Pydantic)؛ خروجی CSV در برابر تزریق فرمول خنثی
  می‌شود؛ پرس‌وجوها پارامتری‌اند.
* **دسترس‌پذیری:** محدودیت نرخ اتمیک به‌ازای نشانی (`SET NX EX` + `INCR` در Redis، پاسخ ۴۲۹)؛ سقف
  اندازهٔ درخواست.

### ۴.۳ جداسازی دامنه

* **نقش‌ها:** auditor < operator < admin؛ auditor فقط می‌خواند، operator لایسنس‌ها را تغییر می‌دهد
  ولی دنبالهٔ ممیزی را نمی‌بیند (تفکیک وظایف)، فقط admin حساب‌ها را مدیریت و حذف دائمی می‌کند.
* **رازها:** نشست مدیران (`SECRET_KEY`)، توکن پورتال (`PORTAL_JWT_SECRET`) و امضای لایسنس (کلید
  Ed25519) کلیدهای جدا دارند؛ افشای یکی دیگری را نمی‌سازد.
* **شبکه:** PostgreSQL، Redis و backend فقط روی شبکهٔ داخلی؛ فقط nginx/Traefik منتشر می‌شوند.
* **مشتریان:** هر پاسخ به یک کلید و یک ماشین گره خورده است؛ پاسخ یک مشتری برای دیگری قابل
  استفاده نیست.

### ۴.۴ عدم‌امکان دور زدن

* هر مسیر `/api/admin/*` به `get_current_admin` (و برای مسیرهای مجاز پیش از تغییر رمز،
  `get_current_admin_any`) و یکی از `require_reader/operator/admin/auditor` وابسته است.
* حساب نیازمند تغییر رمز فقط به `/me`، `/me/password` و `/logout` دسترسی دارد.
* `/internal/portal/*` سه بررسی مستقل دارد که به ترتیب ارزان‌ترین اجرا می‌شوند: IP، امضای JWT،
  یکتایی jti.
* هیچ مسیری لایسنس بدون امضا صادر نمی‌کند؛ هیچ تنظیمی امضا را خاموش نمی‌کند.

## ۵. رمزنگاری

| کاربرد | سازوکار |
|---|---|
| کانال | TLS 1.2/1.3، ECDHE + AES-GCM/ChaCha20؛ Let's Encrypt برای `lic.ngcorion.com` |
| امضای لایسنس و فایل آفلاین | Ed25519 (کتابخانهٔ cryptography) |
| رمز مدیران | scrypt با نمک تصادفی |
| نشست مدیران | JWT HS256، کلید ≥ ۲۵۶ بیت، iss/aud |
| توکن پورتال | JWT HS256 با کلید جدا، iss/aud، jti یک‌بارمصرف |
| مقایسهٔ توکن سازمان | `hmac.compare_digest` (زمان‌ثابت) |

## ۷. محدودیت‌ها

* پورت 80 در چیدمان پیش‌فرض کل برنامه را بدون TLS ارائه می‌کند (برای پراکسی بالادستی قدیمی)؛ در
  پیکربندی ارزیابی‌شده باید بسته یا فقط روی loopback باشد ([راهنما](ADMIN_GUIDE.md) بند ۴.۲).
* Turnstile به سرویس Cloudflare وابسته است (محیط).
* امنیت کلید خصوصی امضا به امنیت میزبان وابسته است (A.HOST)؛ سرور از HSM استفاده نمی‌کند.
