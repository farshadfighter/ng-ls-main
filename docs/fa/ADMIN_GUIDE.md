# راهنمای نصب و راهبری سرور لایسنس NGCorion

| مورد | مقدار |
|---|---|
| محصول | سرور لایسنس NGCorion (API لایسنس + کنسول مدیریت) |
| نسخهٔ محصول | 2.0.0 (`VERSION` در `license_server/app/main.py`؛ `GET /` آن را نشان می‌دهد) |
| نسخهٔ سند | 1.0 |
| مخاطب | مدیر میزبان سرور لایسنس، و کاربران کنسول با نقش‌های admin، operator و auditor |
| الزامات معیار مشترک | AGD_PRE.1 (آماده‌سازی)، AGD_OPE.1 (راهنمای عملیاتی همهٔ نقش‌ها) |
| اسناد مرتبط | [سند معماری](ARCHITECTURE.md)، [هدف امنیتی](../SECURITY_TARGET.md)، `ACME.md`، `SECURITY.md` |

سرور لایسنس لایسنس‌های NGCorion را صادر، فعال، اعتبارسنجی و باطل می‌کند. هر پاسخ آن با کلید خصوصی
Ed25519 امضا می‌شود و NGCorion فقط پاسخ دارای امضای معتبر را می‌پذیرد؛ بنابراین **کلید خصوصی امضا
مهم‌ترین دارایی این سرور است**: هر کس آن را داشته باشد می‌تواند لایسنس بسازد.

## ۱. فرض‌های محیط

| شناسه | الزام برای سازمان |
|---|---|
| A.ADMIN | کاربران کنسول مورد اعتماد و آموزش‌دیده‌اند و هر کدام حساب شخصی دارند. |
| A.HOST | میزبان Docker، فایل `.env` (کلید امضا) و پشتیبان‌ها فقط در اختیار مالک سرور است؛ دسترسی پوسته به میزبان محدود و ثبت می‌شود. |
| A.TIME | زمان میزبان با NTP همگام است (انقضای لایسنس‌ها، نشست‌ها و رکوردهای ممیزی به آن وابسته است). |
| A.NETWORK | فقط پورت 443 از اینترنت باز است؛ پورت 80 و دسترسی مستقیم به کانتینرها از شبکه‌های نامطمئن بسته است (بند ۴.۲). |

## ۳. نصب

### ۳.۱ پیش‌نیازها

* سرور Linux با Docker Engine و Docker Compose ۲٫۲۴٫۴ یا جدیدتر.
* رکورد DNS از نوع A برای `lic.ngcorion.com` به نشانی عمومی سرور (در CDN حالت «DNS only»).
* پورت 443/TCP از اینترنت.
* NTP.

### ۳.۲ دریافت

کد نسخهٔ موردنظر را از تگ `vX.Y.Z` مخزن بگیرید (`git checkout vX.Y.Z`) و بخش «Upgrade notes» در
`CHANGELOG.md` را بخوانید.

### ۳.۳ کلید امضا

روی همین سرور (و نه هیچ جای دیگر):

```
python license_server/scripts/generate_signing_key.py
```

دو خروجی دارد:

* `LICENSE_SIGNING_PRIVATE_KEY` — فقط در `.env` همین سرور. هرگز در گیت، ایمیج، پیام، ایمیل یا
  هیچ ماشین دیگری قرار نگیرد.
* کلید عمومی و شناسهٔ آن — محرمانه نیست؛ باید در کد NGCorion (`app/core/license_keys.py`) قرار
  گیرد تا NGCorion پاسخ‌های این سرور را بپذیرد. همین کلید عمومی بعداً از
  `https://lic.ngcorion.com/api/signing-key` نیز قابل دریافت است.

**چرخش کلید:** کلید جدید بسازید؛ کلید عمومی جدید را **در کنار** کلید قبلی به NGCorion اضافه و
آن نسخه را منتشر کنید؛ سپس سرور را به کلید خصوصی جدید ببرید و در نسخهٔ بعدی NGCorion کلید عمومی
قدیمی را حذف کنید. در صورت افشای کلید خصوصی بی‌درنگ همین روال را اجرا کنید (بند ۹.۲).

### ۳.۴ پیکربندی (`.env`)

`cp .env.example .env` و سپس (`chmod 600 .env`):

| متغیر | مقدار |
|---|---|
| `SECRET_KEY` | تصادفی، دست‌کم ۳۲ نویسه (`openssl rand -hex 32`)؛ کوتاه‌تر، سرور را متوقف می‌کند. |
| `ADMIN_USERNAME`، `ADMIN_PASSWORD` | فقط **اولین** حساب مدیر را در اولین اجرا می‌سازند؛ رمز باید طبق سیاست رمز باشد و در اولین ورود عوض شود. پس از آن خوانده نمی‌شوند. |
| `TURNSTILE_SECRET_KEY` | کلید Cloudflare Turnstile برای فرم ورود (جلوگیری از ربات‌ها). |
| `LICENSE_SIGNING_PRIVATE_KEY` | خروجی بند ۳.۳. |
| `REDIS_PASSWORD` | تصادفی (`openssl rand -hex 32`). |
| `POSTGRES_PASSWORD` | تصادفی و بلند؛ مقدار نمونهٔ `password` را **حتماً** عوض کنید. |
| `PORTAL_JWT_SECRET` | تصادفی و متفاوت از `SECRET_KEY` (اتصال پورتال فروش). |
| `PORTAL_IP_WHITELIST` | نشانی(های) سرور پورتال فروش. |
| `ACME_EMAIL`، `COMPOSE_FILE=docker-compose.yml:docker-compose.acme.yml` | گواهی Let's Encrypt (بند ۴.۱). |

مقادیر پیش‌فرض امنیتی (قابل کوتاه‌تر کردن): `ADMIN_IDLE_TIMEOUT_MINUTES=15`،
`JWT_EXPIRE_HOURS=8`، `ADMIN_MAX_FAILED_LOGINS=5`، `ADMIN_LOCKOUT_MINUTES=15`،
`RATE_LIMIT_PER_MINUTE=60`. `ENABLE_API_DOCS` را در محیط عملیاتی روشن نکنید.

### ۳.۵ اجرا

```
./scripts/gen-self-signed-cert.sh        # گواهی خودامضا برای دسترسی داخلی با IP
docker compose up -d --build
docker compose logs -f traefik           # «Server responded with a certificate.»
```

پایگاه داده با مهاجرت‌های Alembic در شروع کانتینر ساخته/به‌روز می‌شود.

### ۳.۶ بررسی پس از نصب

```
curl -fsS https://lic.ngcorion.com/health
curl -fsS https://lic.ngcorion.com/api/signing-key      # باید همان کلید عمومی بند ۳.۳ باشد
echo | openssl s_client -connect lic.ngcorion.com:443 -servername lic.ngcorion.com 2>/dev/null \
  | openssl x509 -noout -issuer -subject -dates
```

سپس با حساب اول وارد کنسول شوید، رمز را عوض کنید و برای هر نفر حساب شخصی بسازید (بند ۶).

## ۴. پیکربندی امن شبکه و TLS

### ۴.۱ گواهی عمومی (Let's Encrypt)

با `docker-compose.acme.yml`، Traefik پورت 443 را می‌گیرد، برای `lic.ngcorion.com` گواهی Let's
Encrypt (چالش TLS-ALPN-01) می‌گیرد و ۳۰ روز پیش از انقضا خودکار تمدید می‌کند. نام‌های دیگر و دسترسی
با IP، رمزشده و بدون باز شدن، به nginx می‌رسند و گواهی خودامضا را می‌بینند. نشانی واقعی مشتری با
پروتکل PROXY به nginx می‌رسد، پس فهرست مجاز `/internal/`، محدودیت نرخ و لاگ‌ها نشانی درست را
می‌بینند. جزئیات و رفع اشکال: `ACME.md`.

TLS: فقط 1.2 و 1.3؛ رمزهای ECDHE با AES-GCM یا ChaCha20؛ HSTS؛ CSP سخت‌گیرانه؛ نسخهٔ سرور پنهان؛
سقف ۶۴ کیلوبایت برای بدنهٔ درخواست.

### ۴.۲ پورت 80

nginx روی پورت 80 کل برنامه (از جمله کنسول) را **بدون رمزنگاری** ارائه می‌کند؛ این برای چیدمان
قدیمی بود که یک پراکسی بالادستی TLS را پایان می‌داد. در پیکربندی ارزیابی‌شده:

* پورت 80 را در فایروال میزبان از همهٔ شبکه‌ها ببندید، یا آن را فقط روی loopback منتشر کنید:
  `FRONTEND_PORT=127.0.0.1:80`؛
* کنسول را فقط از `https://` باز کنید.

### ۴.۳ دسترسی پورتال فروش

مسیر `/internal/portal/*` فقط از نشانی‌های فهرست مجاز (nginx و `PORTAL_IP_WHITELIST`) و با توکن
امضاشدهٔ کوتاه‌عمر و یک‌بارمصرف پذیرفته می‌شود. نشانی سرور پورتال را در هر دو جا تنظیم کنید.

## ۵. کنسول مدیریت: نقش‌ها

| نقش | دسترسی |
|---|---|
| admin | همه‌چیز: لایسنس‌ها، حساب‌ها، دنبالهٔ ممیزی، حذف دائمی. |
| operator | ساخت و تغییر لایسنس، تغییر طرح، فایل آفلاین، آزاد کردن ماشین، ابطال، همگام‌سازی پورتال. |
| auditor | مشاهدهٔ لایسنس‌ها و طرح‌ها و **مرور و خروجی دنبالهٔ ممیزی**؛ هیچ تغییری نمی‌تواند بدهد. |

اپراتور دنبالهٔ ممیزی را نمی‌بیند تا اقدامات خودش را بازبینی نکند (تفکیک وظایف). سربرگ‌هایی که نقش
شما اجازه نمی‌دهد نمایش داده نمی‌شوند و سرور هم درخواست را رد می‌کند.

### ۵.۱ ورود و نشست

* پیش از ورود، اطلاعیهٔ استفادهٔ مجاز (`ADMIN_LOGIN_BANNER`) نمایش داده می‌شود و Turnstile باید
  تأیید شود.
* **قواعد رمز:** دست‌کم ۱۲ نویسه، دست‌کم سه نوع از: حرف کوچک، حرف بزرگ، رقم، نماد؛ شامل نام کاربری
  نباشد و با رمز فعلی یکی نباشد. رمز با scrypt و نمک تصادفی ذخیره می‌شود.
* **قفل حساب:** پس از ۵ ورود ناموفق، حساب ۱۵ دقیقه قفل می‌شود. همهٔ ردها پاسخ یکسان و زمان یکسان
  دارند.
* **تغییر اجباری رمز:** حساب تازه و رمز بازنشانی‌شده تا تغییر رمز به هیچ بخشی دسترسی ندارد.
* **پایان نشست:** با «Sign out»؛ پس از ۱۵ دقیقه بی‌کاری؛ ۸ ساعت پس از ورود؛ با تغییر رمز یا
  غیرفعال شدن حساب. نشست در سرور نگه داشته می‌شود، پس خروج واقعاً توکن را باطل می‌کند.
* «Password» در نوار بالا: تغییر رمز خودتان.

## ۶. مدیریت حساب‌ها (نقش admin)

سربرگ **Users**:

* **New account:** نام کاربری، نقش، نام کامل، ایمیل، رمز موقت (طبق قواعد رمز). صاحب حساب در اولین
  ورود باید رمز را عوض کند. رمز موقت را از راه امن و جدا از نام کاربری تحویل دهید.
* **تغییر نقش**، **Reset password** (رمز موقت تازه، تغییر اجباری، پایان نشست‌های فعلی)، **Unlock**
  (حساب قفل‌شده)، **Disable** (به‌جای حذف؛ نشست‌ها بی‌درنگ پایان می‌یابند و سوابق باقی می‌ماند).
* هر کار در دنبالهٔ ممیزی ثبت می‌شود.

**بازیابی وقتی هیچ مدیری نمی‌تواند وارد شود** (روی میزبان، ثبت‌شده در دنبالهٔ ممیزی با `"via": "cli"`):

```
docker compose exec backend python -m app.cli list-users
docker compose exec backend python -m app.cli unlock NAME
docker compose exec backend python -m app.cli reset-password NAME
docker compose exec backend python -m app.cli create-user NAME --role admin
```

رمز از ترمینال خوانده می‌شود (نه از خط فرمان) و باید در ورود بعدی عوض شود.

**بازبینی دوره‌ای (هر سه ماه):** حساب‌ها و نقش‌ها را با فهرست کارکنان تطبیق دهید و حساب‌های
بی‌استفاده را غیرفعال کنید.

## ۷. مدیریت لایسنس‌ها (نقش operator یا admin)

### ۷.۱ ساخت

سربرگ **Generate**: سازمان، نام و ایمیل مشتری، **طرح** (Essential ۲۵، Professional ۱۰۰، Business
۲۵۰، Enterprise ۵۰۰/۱۰۰۰/۲۵۰۰، Enterprise Unlimited، یا پایلوت ۵ دارایی یک‌ماهه) و تعداد **بستهٔ
افزودنی** (هر بسته ۵۰ دارایی؛ برای پایلوت و نامحدود نه). خروجی: **کلید لایسنس** و **توکن سازمان**؛
آن‌ها را فقط از راه امن به مشتری بدهید.

### ۷.۲ چرخهٔ عمر

سربرگ **Licenses** ← یک لایسنس:

| کار | توضیح |
|---|---|
| مشاهده | وضعیت، طرح، سقف و تعداد دارایی گزارش‌شده، ماشین متصل (اثر انگشت)، آخرین اعتبارسنجی و heartbeat، فایل‌های آفلاین صادرشده. |
| Save plan | تغییر طرح یا بسته‌های افزودنی؛ در پاسخ بعدی به NGCorion اعمال می‌شود. |
| Release machine | آزاد کردن اتصال به ماشین فعلی تا لایسنس روی ماشین جدید فعال شود (جابه‌جایی یا نصب دوباره). فقط پس از اطمینان از اینکه مشتری ماشین قبلی را کنار گذاشته است. |
| اجازهٔ لایسنس آفلاین | روشن/خاموش کردن امکان صدور فایل لایسنس آفلاین برای این لایسنس. |
| Revoke | ابطال؛ NGCorion در اعتبارسنجی بعدی لایسنس را نامعتبر می‌بیند. |
| Delete (فقط admin) | حذف دائمی؛ برای لایسنس‌هایی که اشتباه ساخته شده‌اند. |

**یک لایسنس، یک ماشین:** اولین فعال‌سازی لایسنس را به اثر انگشت ماشین گره می‌زند؛ ماشین دیگر تا
«Release machine» رد می‌شود.

### ۷.۳ لایسنس آفلاین

برای مشتری بدون اینترنت: محتوای فایل درخواست (`.ngcreq`) که مشتری می‌فرستد را در بخش «Offline
license» لایسنس وارد کنید و «Issue license file». فایل `.ngclic` امضاشده فقط برای همان ماشین و
حداکثر یک سال (و نه بیش از انقضای لایسنس) معتبر است. هر صدور ثبت می‌شود و در فهرست همان لایسنس
دیده می‌شود. سربرگ **Test** فایل درخواست یا لایسنس را بدون هیچ تغییری بررسی و محتوایش را نمایش
می‌دهد.

### ۷.۴ پورتال فروش

سفارش‌های پورتال از مسیر `/internal/portal` لایسنس می‌سازند (ثبت‌شده با actor پورتال). «Sync»
فهرست کاربران و سفارش‌های پورتال را به‌روز می‌کند (operator).

## ۸. دنبالهٔ ممیزی (نقش auditor یا admin)

سربرگ **Audit**: هر رویداد با زمان، کاربر و نقش، نشانی شبکه، اقدام، هدف، نتیجه و جزئیات.

* **ثبت می‌شود:** ورود موفق و ناموفق، قفل حساب، خروج، تغییر و بازنشانی رمز، ساخت و تغییر حساب؛
  ساخت، تغییر طرح، ابطال، حذف، آزاد کردن ماشین و تغییر اجازهٔ آفلاین لایسنس؛ صدور فایل آفلاین؛ سفارش پورتال؛
  فعال‌سازی‌ها و ردهای NGCorion؛ خروجی گرفتن از دنبالهٔ ممیزی؛ شروع سرور (با شناسهٔ کلید امضا).
* **ثبت نمی‌شود:** رمز، توکن یا کلید.
* **جستجو:** بر اساس اقدام، نتیجه، کاربر، هدف (کلید لایسنس) و بازهٔ زمانی؛ **Export CSV** برای
  بایگانی (خنثی‌شده در برابر تزریق فرمول در Excel).
* **حفاظت:** تریگر پایگاه داده هرگونه ویرایش یا حذف رکورد را رد می‌کند. رویدادها هم‌زمان به‌صورت
  JSON در لاگ کانتینر نوشته می‌شوند؛ لاگ را به SIEM سازمان بفرستید.

**بازبینی پیشنهادی (هفتگی):** ورودهای ناموفق و قفل‌ها؛ تغییرات حساب‌ها؛ لایسنس‌های ساخته‌شده،
ابطال‌شده و ماشین‌های آزادشده؛ فایل‌های آفلاین صادرشده؛ ردهای مکرر فعال‌سازی (نشانهٔ استفادهٔ
غیرمجاز از کلید).

## ۹. نگهداری

### ۹.۱ پشتیبان‌گیری

* **پایگاه داده** (روزانه، رمزنگاری‌شده، خارج از سرور):
  `docker compose exec -T postgres sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' | gzip > ls-$(date +%F).sql.gz`
  و سپس رمزنگاری فایل (مثلاً با `age` یا `gpg`) پیش از انتقال.
* **فایل `.env`** (به‌ویژه `LICENSE_SIGNING_PRIVATE_KEY`): یک نسخهٔ رمزنگاری‌شده در گاوصندوق امن
  سازمان، جدا از پشتیبان پایگاه داده. بدون آن، پس از از دست رفتن سرور، NGCorionها پاسخ سرور جدید
  را نمی‌پذیرند تا کلید عمومی جدید در نسخهٔ تازه‌ای از NGCorion منتشر شود.
* حجم `acme` (گواهی Let's Encrypt) نیاز به پشتیبان ندارد ولی آن را پاک نکنید (محدودیت صدور).
* بازیابی را دوره‌ای روی سرور آزمایشی تمرین کنید.

### ۹.۲ رخدادها

| رخداد | اقدام |
|---|---|
| احتمال افشای کلید خصوصی امضا | کلید جدید بسازید و روال چرخش بند ۳.۳ را فوری اجرا کنید؛ دنبالهٔ ممیزی را برای فعال‌سازی‌های غیرعادی بررسی کنید. |
| احتمال نفوذ به یک حساب کنسول | حساب را Disable کنید؛ دنبالهٔ ممیزی آن حساب را مرور و تغییراتش را بازگردانی کنید؛ سپس رمز موقت تازه. |
| ردهای مکرر فعال‌سازی یک کلید از ماشین‌های مختلف | کلید احتمالاً به اشتراک گذاشته شده؛ با مشتری تماس بگیرید و در صورت لزوم Revoke. |
| خطای صدور گواهی | `ACME.md` بخش «When something fails». |

### ۹.۳ به‌روزرسانی

1. پشتیبان پایگاه داده و `.env`.
2. `git fetch && git checkout vX.Y.Z`؛ «Upgrade notes» در `CHANGELOG.md`.
3. `docker compose up -d --build` — مهاجرت‌ها خودکار اجرا می‌شوند.
4. بررسی بند ۳.۶ و یک ورود به کنسول. سرور لایسنس را **پیش از** NGCorionهای وابسته به‌روز کنید.

### ۹.۴ از رده خارج کردن

لایسنس‌ها را به سرور جانشین منتقل یا پایان دهید؛ پشتیبان نهایی؛ کلید خصوصی را فقط اگر سرور
جانشین از همان کلید استفاده می‌کند منتقل کنید (از راه امن)، وگرنه نابود کنید؛ دیسک‌ها را امن پاک کنید.
